## Working conventions

- Documents are living specifications, not one-time deliverables.
- Material product or architecture decisions belong in the decision log.
- Each document begins with a status and last-updated date.
- Unresolved choices are marked `TBD` rather than silently assumed.
- Implementation should link back to the relevant specification where useful.

## Document statuses

- **Draft** — actively being defined and expected to change.
- **Review** — ready for a focused product or technical review.
- **Approved** — accepted as the current source of truth.
- **Superseded** — retained for history but replaced by another document.
